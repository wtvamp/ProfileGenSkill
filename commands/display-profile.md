# display-profile

Shows a **profile-gen** persona to the user as a small always-on-top, click-through overlay window pinned to a corner of its own terminal pane, with the persona's picture (animated, for a GIF) and name. The overlay is a surface the skill owns outright: it consumes no terminal rows, touches no user configuration, and needs no terminal image protocol, so tmux is irrelevant to it. It exits by itself when the session that owns it does.

The skill is installed at `~/.claude/skills/profile-gen` (check there first, then `.claude/skills/profile-gen` under the project root). `PROJECT_ROOT` is this session's working directory — pass it as `--root <PROJECT_ROOT>` (absolute path) on every call.

## Why this works even though your Bash tool's output is invisible

Your shell tool runs with stdout captured for you, not attached to the user's terminal, so nothing you print — plain text or escape sequence — ever reaches their screen. The overlay sidesteps that entirely: `show_profile.py` launches a separate window rather than asking the terminal to draw anything, so it doesn't matter that your stdout goes nowhere. Just run the command and read its JSON report.

Do **not** try to show the persona by printing escape sequences yourself, and don't fall back to the `Read` tool for this — both render through terminal image protocols, which fail under tmux.

## Parse arguments

Parse `$ARGUMENTS` for a mode plus an optional `--slug SLUG` (needed only when more than one persona is discovered and the user wants just one; otherwise every discovered persona is affected).

- **No arguments** — show the persona(s) using their stored preferences.
- **`on`** — turn both `display.image` and `display.name` on, persisted, then show.
- **`off`** — turn both off, persisted, then clear what's currently displayed.
- **`image on|off`** / **`name on|off`** — toggle just that one, persisted, then show.
- **`nsfw on|off|toggle`** — which of the persona's two pictures is shown. A persona has a SFW picture and, optionally, an NSFW one (the same character, same seed and base prompt, regenerated with the NSFW clause added). `on` switches to the NSFW picture, `off` back to the SFW one, and bare `nsfw` or `nsfw toggle` flips to whichever isn't showing. The change is persisted in the persona's `display.variant`, and the profile's `image:` and body picture are rewritten to the selected file, so it survives across sessions until switched back and any other program reading the profile shows the same picture. A persona with no NSFW picture gets a plain error rather than a silent no-op — that one is generated by `/profile-gen`, not here.
- **`autostart on|off`** — whether this persona appears *on its own* at session start. This is a separate question from `image`/`name`, which control what gets drawn when it is shown: `autostart off` leaves a persona fully displayable via `/display-profile` while keeping it from appearing unprompted. Defaults to on.
- **`clear`** — remove the badge/background right now without changing any stored preference.
- **`hook on|off`** — wire up (or remove) a `SessionStart` hook in this project's `.claude/settings.json` so the persona appears automatically at the start of every future session. Delegate the settings.json edit to the **update-config** skill (`Skill` tool) rather than hand-editing JSON. The hook command is:
  ```
  python3 <SKILL_DIR>/scripts/show_profile.py --root "${CLAUDE_PROJECT_DIR:-$PWD}" --autostart-only >/dev/null 2>&1 || true
  ```
  `--autostart-only` is what makes `display.autostart` mean anything — without it the hook would show every persona regardless. The redirect keeps the JSON report out of session context, `|| true` stops a display failure blocking startup, and `async: true` on the hook avoids delaying session start. Note this hook is already installed in `~/.claude/settings.json` and `~/.claude-board/settings.json`; check before adding another. A companion `CwdChanged` hook (`scripts/cwd_changed.py`, installed in the same two files) swaps the badge when the session `cd`s into a directory tree with a different persona; `hook on|off` should add/remove it alongside the SessionStart one. Claude Code **merges** hooks from every applicable settings file rather than letting the nearest one win, so also check whether an ancestor directory's `.claude/settings.json` already registers it — if one does, don't add a second copy in a nested project, or it will fire twice.

## Commands to run

1. For a toggle mode (`on`/`off`/`image ...`/`name ...`/`nsfw ...`):
   ```
   python3 <SKILL_DIR>/scripts/toggle_display.py --root <PROJECT_ROOT> [--slug SLUG] [--image on|off] [--name on|off] [--autostart on|off] [--variant sfw|nsfw|toggle]
   ```
   `nsfw on` is `--variant nsfw`, `nsfw off` is `--variant sfw`, and bare `nsfw`/`nsfw toggle` is `--variant toggle`. The JSON's `display.variant` is what actually got stored — report that rather than assuming the flip landed, since switching to a variant the persona has no picture for is refused with `{"error": "..."}` and a nonzero exit.
   Prints `{"slug", "markdown_path", "display": {...}}` per persona changed, or `{"error": "..."}` (nonzero exit) if no persona was found — report that plainly; the usual cause is that no persona has been generated in this project yet, so suggest `/profile-gen`.

2. Then show (or clear):
   ```
   python3 <SKILL_DIR>/scripts/show_profile.py --root <PROJECT_ROOT> [--slug SLUG]
   python3 <SKILL_DIR>/scripts/show_profile.py --root <PROJECT_ROOT> --clear     # for `off` / `clear`
   ```
   Prints one JSON object per persona: `{"name", "mode", "variant", "requested_variant", "variant_fell_back", "hud", "badge", "background", "inline"}`. `variant` is which picture was actually drawn; `variant_fell_back: true` means the requested one doesn't exist and the other was used. `mode` is `hud` wherever the overlay is supported (macOS, and Windows once tested) and `inline` elsewhere; `hud: true` means the overlay actually launched. Don't pass `--autostart-only` here — that's for the hook; an explicit `/display-profile` should show the persona regardless of its autostart setting.

## Report

Tell the user which persona is now displayed (by name), which picture variant is showing, and whether the overlay actually launched, based on the JSON report's fields rather than an assumption. If `hook on/off` was requested, confirm what update-config changed in `.claude/settings.json`.
